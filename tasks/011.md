# 011 — Responsividade da Tela de Transações (Mobile)

## Objetivo

Melhorar a experiência de uso da tela de Transações em dispositivos móveis. Atualmente, a tela utiliza o componente genérico `DataTable`, que não se adapta bem a telas pequenas (ocasionando scroll horizontal ou quebra de colunas). O objetivo é criar uma visualização em formato de lista/cards exclusiva para mobile, garantindo que o app siga o princípio de "Mobile First" e a regra do `AGENTS.md` (usar classes utilitárias para quebrar layout no `md`).

## Contexto

- **Rota:** `src/app/[locale]/(app)/transactions/`
- **Componentes Principais:** `transactions-view.tsx`, `DataTable`, `SummaryCards`.
- **Regras de Negócio e UX:**
  - A quebra de layout deve ocorrer no breakpoint `md` (768px).
  - Telas maiores (`md:block`) continuam exibindo a `DataTable` atual.
  - Telas menores (`block md:hidden`) devem ocultar a tabela e exibir o novo componente de lista mobile.
  - O agrupamento cronológico (saldo diário e data) que já existe na tabela deve ser mantido na lista mobile.

## Recursos

### 1. Lista de Transações Mobile (Cards/List Items)
- **Agrupamento:** Exibir um cabeçalho para cada dia (ex: "15/11/2026") com o saldo consolidado do dia ao lado, exatamente como é feito na tabela hoje.
- **Card de Transação:**
  - Lado esquerdo: Ícone da categoria, Descrição e Nome da conta.
  - Lado direito: Valor (com cor vermelha para despesa, verde para receita) e botão de reticências (Dropdown Menu) para ações.
- Ações no Dropdown Menu: Editar, Duplicar, Excluir.

### 2. Cards de Resumo (SummaryCards)
- Revisar a responsividade dos 3 cards no topo da tela (Receitas, Despesas, Balanço). Se estiverem espremidos no mobile, garantir que eles empilhem um em cima do outro (`flex-col` ou `grid-cols-1`) ou formem um carrossel horizontal.

### 3. Filtros e Ações
- O botão de "Filtros" (Sheet) já foi convertido para responsivo. Garantir apenas que a barra de ações principais (Filtros + Botão Adicionar) ocupe bem o espaço no mobile, com o botão "Adicionar" podendo encolher para mostrar apenas um ícone `+` ou ficar em linha com os filtros.

## Passos

1. **Criar `_components/table/transaction-mobile-list.tsx`:**
   - O componente deve receber a mesma lista `transactions`, o mapeamento de saldo por data (`balanceByDateKey`) e as funções de ação (`onEdit`, `onDuplicate`, `onDelete`).
   - Implementar a renderização visual usando Tailwind (flex, gap, ícones).
2. **Atualizar `_components/transactions-view.tsx`:**
   - Renderizar os dois componentes lado a lado de forma lógica, usando classes do Tailwind para ocultar/mostrar:
     ```tsx
     <div className="hidden md:block">
       <DataTable ... />
     </div>
     <div className="block md:hidden">
       <TransactionMobileList ... />
     </div>
     ```
   - Isso evita o uso de hooks (`useIsMobile()`) para a listagem principal, prevenindo erros de "Hydration Mismatch" (pois o servidor não sabe o tamanho da tela e renderizaria diferente do cliente).
3. **Revisar CSS do `SummaryCards`:** Validar se no mobile as caixas estão empilhando corretamente.

## Pronto quando

- Acessar a tela de transações no celular e ver uma lista de cards amigável, sem scroll horizontal, agrupada por data.
- Todas as ações do menu (editar, duplicar, excluir) funcionarem na versão mobile através do botão de reticências (Dropdown).
- No Desktop, a tabela antiga continuar aparecendo sem alterações.
- Nenhum erro de Hydration no console durante o carregamento inicial.
- `pnpm lint` e `pnpm build` passando limpo.
