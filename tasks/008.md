# 008 — Tela de Cartões de Crédito (Credit Cards)

## Objetivo

Criar a tela de gestão exclusiva para Cartões de Crédito. Diferente das contas comuns, um cartão de crédito no sistema exige informações adicionais (limite, dias de fechamento e vencimento) e suporta o gerenciamento de múltiplos cartões físicos (ex: titular, cartões virtuais) que compartilham o mesmo limite e fatura.

## Contexto

- **Rota:** `src/app/[locale]/(app)/credit-cards/`
- **Modelos Principais (Prisma):** `Account` (onde `type = CREDIT_CARD`), `CreditCardDetails`, `Card`.
- **Nota:** não há mais modelagem de banco/instituição no schema (ver
  `tasks/007.md` e o comentário no topo do `prisma/schema.prisma`) — os
  itens abaixo que mencionam Instituição/Banco não se aplicam mais.
- **Regras de Negócio:**
  - A conta raiz continua sendo do modelo `Account`, mas seu tipo será rigidamente `CREDIT_CARD`.
  - Essa conta não exibe um saldo simples, mas sim o limite disponível e o uso distribuído pelas `Invoice` (Faturas).
  - Um registro em `CreditCardDetails` é obrigatório para essa conta (1:1), contendo `limit`, `closingDay`, e `dueDay`.
  - Múltiplos cartões físicos/virtuais podem ser atrelados via tabela `Card`.

## Recursos

### 1. Lista de Cartões de Crédito
- Visualização focada no limite de crédito (Limite Total, Limite Disponível) e talvez um resumo da fatura atual.
- Menu de contexto (editar, inativar/arquivar, excluir).

### 2. Formulário de Criação/Edição (Sheet)
- Campos base: Nome (ex: "Cartão Nubank").
- O tipo é invisível para o usuário, fixado internamente como `CREDIT_CARD`.
- Campos do `CreditCardDetails`:
  - **Limite:** Campo de valor (`dinero.js`, convertido para Prisma Decimal).
  - **Dia de Fechamento:** Campo numérico (1 a 31).
  - **Dia de Vencimento:** Campo numérico (1 a 31).

### 3. Gestão de Cartões Físicos (`Card`)
- O usuário deve poder cadastrar os plásticos associados a essa conta de crédito.
- Campos por cartão físico: Nome (ex: "Físico Principal", "Virtual Online"), 4 últimos dígitos (opcional).
- O formulário pode usar um array dinâmico via TanStack Form (adicionar/remover cartões na mesma tela de edição da conta).

### 4. Arquivamento (Status)
- Mudar o status da conta para `INACTIVE`. Assim, esse cartão para de aparecer como opção de pagamento no momento de registrar uma transação.

## Passos

1. **`schema.ts`**: Criar esquemas Zod (ex: `creditCardAccountSchema`, `creditCardDetailsSchema`, `cardSchema`).
2. **`actions.ts`**: Implementar Server Actions específicos para a gestão de cartões de crédito:
   - `listCreditCards()`: Busca apenas `Account` onde `type == 'CREDIT_CARD'`, incluindo relações (`creditCardDetails`, `cards`).
   - `createCreditCard(data)` / `updateCreditCard(id, data)`: Salvar a conta. Envolve criar atomicamente (via `$transaction`) a `Account`, `CreditCardDetails` e os registros em `Card`.
   - `deleteCreditCard(id)` / `toggleCreditCardStatus(id)`.
3. **`_components/`**:
   - `credit-cards-view.tsx`: Listagem dos cartões de crédito.
   - `form/credit-card-sheet.tsx`: Formulário de criação/edição.
4. **Mensagens (`scrn-credit-cards.json`)**: 
   - Adicionar traduções (pt-BR e en) para campos específicos (Limite, Fechamento, Vencimento, Cartões Físicos). Seguindo o padrão `AGENTS.md`.

## Pronto quando

- A tela `/credit-cards/` listar corretamente os cartões de crédito criados.
- Ao criar/editar um cartão, as entidades `Account`, `CreditCardDetails` e `Card` (array) forem atualizadas corretamente no banco de dados, em uma transação atômica.
- Nenhum texto hardcoded, tudo passando pelo `next-intl`.
- `pnpm lint` e `pnpm build` sem erros.
